# 設計: room オーバーレイ（ニコニコ風コメント共有）

2026-07-03 ブレインストーミングで確定した設計。

## 概要

ura-talk の出力先に **`room`** を追加する。各メンバーのローカルで文字化した発話（またはタイプ入力）を軽量な中継サーバの「ルーム」に流し、参加者全員の画面に**ニコニコ動画風の流れるコメント**として表示する。MTG アプリ（Gather / Meet / Zoom …）には一切依存せず、透過オーバーレイを画面全体に被せることでどのツールの上でも使える。

- 対象プラットフォーム: **macOS のみ**（既存の Go + cgo 資産を拡張）
- 音声パイプライン（VAD → whisper → LLM 整形）は変更なし
- **2026-07: オーバーレイ専用に一本化**。`keystroke` / `slack` の単体出力モードと OAuth/Keychain 一式を削除し、入口をオーバーレイに統一した（「入力がどこへ行くか」の認知負荷を下げるため）。Slack 連携は下流のミラー（v1.2）としてのみ残す

## 全体アーキテクチャ

```
[各メンバーの Mac]                        [Cloudflare Workers]
 mic → VAD → whisper → LLM整形 ─┐
 ホットキー入力バー ────────────┼→ WebSocket ──→ Durable Object (room)
                                │                 │ 全参加者にブロードキャスト
 透過オーバーレイ ←─────────────┴←────────────────┘
```

自分の発話も**サーバのエコー経由で表示**する（全員の画面で同じものが同じ順序で流れる）。ネットワーク断の間は自分のコメントだけローカルに流すフォールバックを持つ。

### C2C（サーバレス）を採らない理由

WebRTC DataChannel はシグナリングサーバが結局必要な上、企業ネットワークでは NAT 越えに TURN（= 中継サーバ）が要るケースが多く「サーバ無し」は実質成立しない。テキストのみで帯域はほぼゼロなので、最初から軽量 WebSocket リレーの方がシンプルで確実。

## サーバ（Cloudflare Workers + Durable Objects）

TypeScript 製。リポジトリ内 `server/` に同居させる。エンドポイントは 2 つだけ。

| エンドポイント | 役割 |
|---|---|
| `POST /rooms` | 128bit ランダムトークンを発行して返す（ルーム作成） |
| `GET /r/<token>/ws` | WebSocket にアップグレードし、トークンに対応する Durable Object へ接続 |

- ルーム = Durable Object 1 インスタンス。接続中ソケットへのファンアウトのみ
- **永続化なし**。会議が終わりアイドルになれば DO は自然消滅し、履歴はどこにも残らない
- WebSocket Hibernation API を使い、アイドル時の課金をほぼゼロに（無料枠で運用可能な見込み）
- 接続ごとの簡易レートリミット（コメント連投対策）を入れる

## プライバシー: E2E 暗号化

ルーム作成時に**クライアント側で** AES-GCM の鍵を生成し、共有 URL のフラグメントに載せる:

```
https://<worker>/r/<token>#k=<base64url 鍵>
```

- フラグメントは HTTP リクエストで送信されないため、**サーバ（= Cloudflare）にも本文を見せない**
- サーバは暗号文を中継するだけ。既存の「発話をローカルから出さない」思想の延長
- URL 自体がアクセス制御（トークンは推測不能）。認証・アカウントは作らない

## 匿名性と発言者名

既定は**匿名（ニコニコ完全踏襲）**。メッセージに名前を含めず、クライアントが起動時に生成するランダム色だけを添える（同一人物の発言は色で追える）。

**記名モード（v1.1・実装済み）**: メニューの「新規ルームを作成 — 匿名 / — 記名」で作成時に選ぶ。サーバに設定は持たせず、共有 URL のフラグメントに `&n=1` を含めることで全参加者のモードを揃える。表示名は config の `display_name` を最優先、未設定なら記名ルームの作成/参加時にダイアログで入力させ、内部ファイル（`~/Library/Application Support/ura-talk/display_name`）に保存して次回以降は聞かない（macOS ユーザー名の自動使用はしない）。記名ルームでは各コメントに `[表示名]` が付く。

## メッセージプロトコル

WebSocket 上の JSON（本文部分は E2E 暗号化）:

```jsonc
{ "v": 1, "ct": "<AES-GCM暗号文 base64>", "iv": "<nonce>" }
// ct を復号すると: { "text": "それな", "color": "#ff8800", "name": "" }
```

## クライアント（既存 Go アプリの拡張）

| パッケージ | 役割 |
|---|---|
| `internal/room/` | WebSocket クライアント。接続・自動再接続（指数バックオフ）・AES-GCM 暗号化送受信 |
| `internal/overlay/` | 背景透明・クリック貫通（`ignoresMouseEvents`）・最前面の `NSWindow` を画面全体に。コメントは `CATextLayer` + Core Animation で右→左に約 8 秒で横断（GPU 合成で CPU をほぼ食わない）。白文字 + 黒縁取り、重なり回避のレーン割り当て |
| `internal/inputbar/` | 別ホットキー（既定 `右⌥`、config 可）で画面下部に Spotlight 風入力欄。Enter で送信して閉じる、Esc でキャンセル |

- メニューバーに「ルーム作成（URL をクリップボードへ）」「URL で参加」「退出」を追加。参加中はアイコン/メニューで状態表示
- config 追加: `output: "room"`, `room.server`（Worker の URL）, `room.input_hotkey`, `display_name`（記名モード用・後回し）

## 使い方の流れ

1. ホストがメニューバーから「ルーム作成」→ URL がクリップボードに入る → Slack 等で共有
2. メンバーは「URL で参加」に貼るだけ
3. `右⌘` で音声、`右⌥` で文字入力。全員のオーバーレイにコメントが流れる
4. 退出（または全員切断でルームが自然消滅）

## エラーハンドリング

- 切断時はオーバーレイ隅に小さく接続状態を表示しつつ自動再接続
- 再接続中の自分のコメントはローカル表示のみ。**溜めて再送はしない**（リアルタイム性優先）
- 復号失敗（鍵違い）のメッセージは黙って捨てる

## テスト

- Go unit test: プロトコルのエンコード/デコード、暗号化ラウンドトリップ、レーン割り当て
- サーバ: vitest + miniflare（接続・ファンアウト・レートリミット）
- オーバーレイの見た目・クリック貫通は実機確認

## ロードマップ

1. **v1**: 匿名・音声 + 入力バー・E2E・Workers デプロイ
2. **v1.1**（実装済み）: 記名モード（ルーム作成時に匿名/記名を選択）
3. **v1.2**（実装済み）: Slack ミラー（下記）
4. 以降の候補: コメント密度に応じた自動フォント縮小、Windows クライアント（Tauri 等で表示側のみ先行）

## Slack ミラー（v1.2・実装済み）

サーバは何も保持しないため、記録を残したいルームは Slack チャンネルへ流し込めるようにする。

- **クライアント側でミラーする**。E2E のためサーバは本文を復号できないが、復号済みコメントは全参加者のクライアントが持っている。参加者のうち 1 人（通常はホスト）がミラー役になり、自分のクライアントから `internal/slack` 経由で転送する
- **Slack 連携が必要なのはミラー役 1 人だけ**。他のメンバーは設定不要
- **投稿スタイル**: メニューの「Slack に記録」を ON にすると親メッセージを 1 本投稿し、以降のコメントはスレッド（`thread_ts`）にぶら下げてチャンネルを汚さない。退出・切断で自動停止
- **名義**: **bot token（xoxb）でアプリ名義投稿**に一本化した。匿名ルームなら Slack 上でも匿名を保てる（記名ルームは `[表示名]` 付き）。OAuth/Keychain はオーバーレイ専用化で撤去したため、user token（本人名義）は採らず、bot token を config か環境変数 `URATALK_SLACK_BOT_TOKEN` で渡す
- **チャンネル指定**: 当初案の「URL フラグメント `&slack=` でルームに紐づけて透明性を担保」は見送り、ミラー役の config（`room.slack_channel`）で指定する方式にした。理由: 作成メニューの組み合わせ爆発（匿名/記名 × 記録有無）を避け、ミラーを「ルーム作成時の選択」ではなく「参加後のトグル」として後付けできるようにするため。透明性（他メンバーへの録画告知）が必要になれば URL フラグメント方式を後で足す
- **割り切り**: ミラー役が退出したらログは止まる。ミラー役が複数いると二重投稿になるので Slack 設定は 1 人だけにする。引き継ぎの調停（リーダー選出）は必要になってから検討
